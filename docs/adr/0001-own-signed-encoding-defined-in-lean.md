# BOGO's own signed encoding, defined in Lean

The bytes an approver signs use BOGO's own tagged, length-prefixed encoding, defined in Lean, instead of canonical JSON or deterministic CBOR. JSON arguments become a tree with sorted object keys, and numbers keep their exact decimal text, so `4700`, `4700.0` and `4.7e3` stay distinct. This keeps the proof that different requests never encode the same short, and it means nothing quietly turns a number into a float. The Swift and Rust implementations are checked against test vectors generated by the Lean encoder.
